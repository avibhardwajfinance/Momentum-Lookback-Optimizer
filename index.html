CODE FLOW notebook order, run each cell once top to bottom
1. Load data and fix dates

Two files are read: Test_price_data.csv and Test_mcap_data.csv, 30 stocks each.

  • Price dates are written DD-MM-YYYY, market cap dates YYYY-MM-DD. Each is parsed with its own format so no day and month get swapped.
  • Dates become the index, then a check confirms both files cover the same dates and the same 30 stocks.
  • The date cell changes the tables it reads, so running it twice gives an error. Restart and run all instead.
2. Clean fake price spikes

The data has about 5,000 one-day spikes in both prices and market caps (example THOM.NS: 9.06, 29.12, 9.04).

  • Each value is compared with the rolling median of the surrounding 7 days.
  • If it is more than 30% away from that median, it is replaced by the median.
  • Both prices and market caps are cleaned.
  • Why it matters: without cleaning, the 189-day lookback shows about 187 million percent cumulative return, which is not plausible.
3. Build the monthly calendar
  • For each month, the rebalance date is the first trading day of that month.
  • The calculation date is the trading day just before it.
  • This gives 246 pairs of (calculation date, rebalance date).
  • Using the previous day's data for decisions is what prevents look-ahead bias.
4. Momentum score and ranking 
momentum = price[calc_date] / price[calc_date - L trading days] - 1
  • L is counted in trading days (rows), not calendar days.
  • The 30 stocks are ranked by momentum, rank 1 being the highest.
5. Pick the 10 holdings (buffer rule)
  • Always hold exactly 10 stocks.
  • A stock already held is kept if its new rank is 12 or better, otherwise sold. This reduces needless turnover.
  • Empty spots are filled with the best-ranked stocks not already held.
  • The first month has no holdings, so it takes the top 10.
6. Weights: market cap with a 20% cap
  • Start with weights proportional to market cap among the 10 holdings.
  • Any stock above 20% is cut to 20%.
  • The excess is shared among the other stocks in proportion to market cap.
  • This is repeated until no stock exceeds 20%, since redistribution can push another stock over.
7. Trade timing and daily returns
  • Trades happen at the close of the rebalance day.
  • New weights earn returns from the next day, so the rebalance day itself uses the old weights.
  • Weights are held until the next rebalance and daily portfolio return is the weighted sum of stock returns.
  • No transaction costs, taxes or slippage.
8. Manual test, then automation
  • The logic is first tested by hand on one lookback (189) for two months, so each step can be checked.
  • Then loops run it for all 5 lookbacks (21, 63, 126, 189, 252) and all 246 months. The notebook prints done 21 ... done 252.
  • Keep the whole loop in one cell, with the last two lines indented inside for lookback.
9. Metrics and final answer
  • Sharpe = mean daily return / sample std of daily return x sqrt(252), risk-free rate 0%.
  • Cumulative return = growth of the portfolio over all 5,083 days, minus 1.
  • CAGR = (1 + cumulative return)^(252 / trading days) - 1.
  • The lookback with the highest Sharpe wins: 189 days, Sharpe 0.992, cumulative return 8,649.0 %, CAGR 24.82 %.
  • Results are shown as a coloured table (needs jinja2) and charts.
10. Where a reviewer could read the rules differently
  • Day 1: whether returns start on the rebalance day or the day after (this project uses the day after).
  • CAGR convention: trading days over 252 versus calendar years.
  • Data cleaning: whether to clean spikes at all, and how. Results change a lot without it.
11. Setup and troubleshooting
  • Colab: put both CSVs in My Drive/Colab Notebooks, mount Drive, check the two file paths at the top.
  • Local: pip install pandas numpy matplotlib jinja2 jupyter, keep the CSVs next to the notebook, set the paths to just the file names.
  • Non-numeric error in the cleaning cell: restart the session and run all cells in order.
  • Only done 252 printed: the loop is split across cells or mis-indented.
  • KeyError in results: run setup once, then the three loop cells, then results.
